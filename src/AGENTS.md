# Host

- Keep Zustand state data-only in `src/store`; methods live on `NessoStore`, with `useNessoStore` for React.
- `NessoStore` exposes typed operations and convenience methods for graph, views, navigation, viewport, preferences, and reset. All public writes delegate to `applyOperations`; registration and persistence diagnostics remain internal. Editing forms stay in the host. Collapsed sections are optional preferences with stable ids; unspecified sections are open, and their state is shared across selections and documents.
- Persist versioned document/workspace and preference records separately using localStorage. Restore and validate before autosave, resolve active plugin ids during registration, debounce durable changes, and flush on page hide. Never overwrite unreadable records; report storage failures visibly and keep editing available in memory.
- All graph edits share one commit boundary: validate with `validateGraph`, reject atomically with `SchemaError`, then reconcile selection. Keep at least one concept; deletion removes incident relations. Remove non-vocabulary relation types when their last use in the whole graph is removed or retyped; keep unrelated unused definitions. No blanket normalization.
- `src/data/seed-graph.json` and `seed-views.json` seed only the first document. `NessoStore.resetGraph` atomically creates a fresh single-concept graph with no saved views, preserving preferences. Legacy deleted records and unreadable documents start with one fresh concept instead of the seed.
- State writes prepare immutable candidates with structural sharing: never mutate published state, and preserve references to unchanged parts. No-ops do not publish or notify; batches commit atomically with at most one notification.
- Copy each edited list once per batch and record touched entities as history deltas; keep full graph validation.
- Host-owned undo/redo stores up to 100 document deltas in memory, never persisted. Expose `undo`/`redo` commands and `history` flags on the injected store; the canvas offers buttons next to delete. Include graph and saved-view edits, including pins; exclude navigation, selection, viewport and preferences. Restore effects exactly without replaying domain requests or automatic cleanup. Preserve current navigation when valid and reconcile selection. New document edits clear redo; reset clears all history, including in mixed batches. Explicit interaction IDs group adjacent label/position writes.
- `applyOperations` applies typed `NessoOperation` writes in order to candidate graph, workspace, preferences, and selection, then validates and publishes only the final state. Creation and reset operations take explicit stable IDs; convenience methods generate IDs. New concepts join the view active at their operation. Empty and cancelling batches do not notify; cancelled graph changes discard their implicit selection effects without discarding explicit selection or navigation.
- Update `viewGraph` in the commit boundary and on view/membership changes. Membership edits preserve off-view selection; graph deletion prunes saved memberships atomically.
- Use static registration and small lookups; no lifecycle, runtime loading, uninstall, dynamic permission system, or event bus. Plugins declare operation kinds before initialization; inject a store with a copied allowlist that checks the whole batch before applying it. Host and plugin stores share command helpers; no helper bypasses the check. Allow multiple renderers/vocabs, validate registration/activation, and keep one valid active id for each in state; renderer components stay in the registry.
- Vocabulary switching never rewrites the graph; using a new type adds its definition atomically.
- Keep app-specific components in `src/components/app`. Concept/relation editing and membership forms live in the Inspector; view creation lives in the Explorer. Map canvas commands and gestures to domain writes.
