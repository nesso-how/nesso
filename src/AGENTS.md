# Host

- Keep Zustand state data-only in `src/store`; methods live on `NessoStore`, with `useNessoStore` for React.
- Host-owned view editing, theme activation, panel sizing, and section collapse commands live on `host.ui`, not the injected `NessoStore`. Collapsed sections are optional preferences with stable ids; unspecified sections are open, and their state is shared across selections and documents.
- Persist versioned document/workspace and preference records separately using localStorage. Restore and validate before autosave, resolve active plugin ids during registration, debounce durable changes, and flush on page hide. Never overwrite unreadable records; report storage failures visibly and keep editing available in memory.
- All graph edits share one commit boundary: validate with `validateGraph`, reject atomically with `SchemaError`, then reconcile selection. Keep at least one concept; deletion removes incident relations. Remove non-vocabulary relation types when their last use in the whole graph is removed or retyped; keep unrelated unused definitions. No blanket normalization.
- `src/data/seed-graph.json` and `seed-views.json` seed only the first document. `host.ui.resetGraph` atomically creates a fresh single-concept graph with no saved views, preserving preferences. Legacy deleted records and unreadable documents start with one fresh concept instead of the seed.
- Domain writes prepare immutable candidates with structural sharing: never mutate published state, and preserve references to unchanged graph parts. Graph domain no-ops do not publish or notify; position batches commit atomically with at most one notification.
- All domain writes delegate to typed `applyOperations` batches. Apply operations in order to immutable candidates, then validate and publish only the final graph. Empty and cancelling batches do not notify. Creation operations take explicit stable IDs so later operations can reference them; single-write helpers generate IDs.
- Update `viewGraph` in the commit boundary and on view/membership changes. Membership edits preserve off-view selection; graph deletion prunes saved memberships atomically.
- Use static registration and small lookups; no lifecycle, runtime loading, uninstall, permissions, or event bus. Allow multiple renderers/vocabs, validate registration/activation, and keep one valid active id for each in state; renderer components stay in the registry.
- Vocabulary switching never rewrites the graph; using a new type adds its definition atomically.
- Keep app-specific components in `src/components/app`. Concept/relation editing and membership forms live in the Inspector; view creation lives in the Explorer. Map canvas commands and gestures to domain writes.
