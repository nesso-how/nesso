# Host

- Keep Zustand state data-only in `src/store`; methods live on `NessoStore`, with `useNessoStore` for React.
- Keep the shared plugin state vocabulary- and renderer-independent. Host-only workspace tag filters and preference panel sizes extend the shared state; their commands live on `host.ui`, not the injected `NessoStore`.
- Persist versioned document/workspace and preference records separately using localStorage. Restore and validate before autosave, resolve active plugin ids during registration, debounce durable changes, and flush on page hide. Preserve unreadable records and report storage failures visibly; edits continue in memory.
- All graph edits share one commit boundary: validate with `validateGraph`, reject atomically with `SchemaError`, then reconcile focus/selection. Keep at least one concept; deletion removes incident relations. No blanket normalization or pruning unused types.
- The seed is only for first initialization. `host.ui.resetGraph` atomically replaces the document with a fresh single-concept graph and resets its workspace, preserving preferences. Legacy deleted records and unreadable documents start with one fresh concept instead of the seed; unreadable records remain protected from autosave.
- Domain writes prepare immutable candidates with structural sharing: never mutate published state, and preserve references to unchanged graph parts. Graph domain no-ops do not publish or notify; position batches commit atomically with at most one notification. Keep full-document validation at the commit boundary.
- All domain writes delegate to typed `applyOperations` batches. Apply operations in order to immutable candidates, then validate and publish only the final graph. Empty and cancelling batches do not notify. Creation operations take explicit stable IDs so later operations can reference them; single-write helpers generate IDs.
- Materialize `viewGraph` (focus neighborhood or whole document) in the commit boundary and on `setFocus`/`setView`; it is the single writer. `setFocus` implies focus view.
- Use static registration and small lookups; no lifecycle, runtime loading, uninstall, permissions, or event bus. Allow multiple renderers/vocabs, validate registration/activation, and keep one valid active id for each in state; renderer components stay in the registry.
- Vocabulary switching never rewrites the graph; using a new type adds its definition atomically.
- The app interface lives in `src/components/app`; reusable primitives live in `src/components/ui`. Editing forms live in the Inspector; the canvas exposes only selection-scoped commands (add concept, delete selected) and gestures, all mapped to domain writes — no forms in plugins.
